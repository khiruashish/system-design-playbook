    11. Quorum Replication: R + W > N¶

    L3 ★★★ · Tunable consistency, versioned values, read repair, availability

    Problem¶

    Simulate Dynamo-style replication with N replicas, write quorum W and read quorum R. Show that R + W > N gives reads the latest acknowledged write, that weaker settings can read stale data, and how failures affect availability.

    Key idea¶

    When R + W > N, every read set overlaps every write set in at least one replica, so the highest-versioned value seen is the latest acknowledged write. The read also repairs stale replicas it saw. With R + W ≤ N you get lower latency and higher availability, but stale reads become possible. Each operation needs enough live replicas to reach its quorum.

    flowchart LR subgraph W2["write v2 → W=2"] r1a[r1 ✓] r2a[r2 ✓] end subgraph R2["read → R=2"] r0b["r0 (v1, stale)"] r2b["r2 (v2)"] end r2a -. overlap .- r2b R2 --> NV["newest = v2; repair r0"]

    Solution¶

    QuorumReplication.java
    import java.util.*;

/** Problem: Dynamo-style replication with N replicas, write quorum W and read quorum R; show why R + W > N gives fresh reads. */
public class QuorumReplication {

    record Versioned(String value, long version) { }

    static final class Replica {
        final String name; boolean up = true;
        final Map<String, Versioned> data = new HashMap<>();
        Replica(String name) { this.name = name; }
    }

    static final class Cluster {
        final List<Replica> replicas; final int w, r;
        long clock;                                             // production: per-key version / vector clock / HLC
        Cluster(int n, int w, int r) {
            this.replicas = new ArrayList<>(); for (int i = 0; i < n; i++) replicas.add(new Replica("r" + i));
            this.w = w; this.r = r;
        }

        /** Write to replicas in order until W acks (a coordinator would send to all and wait for W). */
        boolean write(String key, String value, List<Integer> reachableOrder) {
            Versioned v = new Versioned(value, ++clock);
            int acks = 0;
            for (int i : reachableOrder) { Replica rep = replicas.get(i); if (!rep.up) continue; rep.data.put(key, v); if (++acks == w) return true; }
            return false;                                       // not enough replicas: fail the write (sloppy quorum would hand off)
        }

        /** Read R replicas, return the highest version, and READ-REPAIR stale ones. */
        Optional<String> read(String key, List<Integer> askOrder, List<String> repairs) {
            List<Replica> asked = new ArrayList<>();
            for (int i : askOrder) { Replica rep = replicas.get(i); if (rep.up) asked.add(rep); if (asked.size() == r) break; }
            if (asked.size() < r) throw new IllegalStateException("read quorum not met");
            Versioned newest = null;
            for (Replica rep : asked) { Versioned v = rep.data.get(key); if (v != null && (newest == null || v.version() > newest.version())) newest = v; }
            if (newest == null) return Optional.empty();
            for (Replica rep : asked) {
                Versioned v = rep.data.get(key);
                if (v == null || v.version() < newest.version()) { rep.data.put(key, newest); repairs.add(rep.name); }
            }
            return Optional.of(newest.value());
        }
    }

    public static void main(String[] args) {
        List<String> repairs = new ArrayList<>();

        // N=3, W=2, R=2: R + W = 4 > 3, so every read set overlaps every write set in >= 1 replica.
        Cluster strong = new Cluster(3, 2, 2);
        strong.write("cart", "v1:[apple]", List.of(0, 1, 2));          // lands on r0, r1
        strong.write("cart", "v2:[apple,milk]", List.of(1, 2, 0));     // lands on r1, r2 (r0 still has v1)
        String read = strong.read("cart", List.of(0, 2, 1), repairs).orElseThrow();   // asks r0 (stale) + r2 (fresh)
        System.out.println("N=3 W=2 R=2 -> read " + read + ", read-repaired " + repairs);
        check(read.startsWith("v2") && repairs.equals(List.of("r0")), "overlap guarantees the newest version");

        // N=3, W=1, R=1: R + W = 2 <= 3, reads can miss the latest write.
        Cluster fast = new Cluster(3, 1, 1);
        fast.write("cart", "v1", List.of(0, 1, 2));
        fast.write("cart", "v2", List.of(1, 0, 2));
        String stale = fast.read("cart", List.of(0), new ArrayList<>()).orElseThrow();
        System.out.println("N=3 W=1 R=1 -> read " + stale + "  <-- stale: read set {r0} and write set {r1} don't overlap");
        check(stale.equals("v1"), "no overlap, stale read possible");

        // Availability: one replica down, W=2/R=2 still works; two down, writes fail.
        strong.replicas.get(2).up = false;
        System.out.println("1 of 3 down: write ok? " + strong.write("cart", "v3", List.of(0, 1, 2)) + ", read = " + strong.read("cart", List.of(0, 1, 2), new ArrayList<>()).orElseThrow());
        strong.replicas.get(1).up = false;
        System.out.println("2 of 3 down: write ok? " + strong.write("cart", "v4", List.of(0, 1, 2)));
        check(!strong.write("cart", "v5", List.of(0, 1, 2)), "quorum unavailable");
        System.out.println("PASS");
    }

    static void check(boolean ok, String what) { if (!ok) { System.out.println("FAILED: " + what); System.exit(1); } }
}

    Walkthrough¶

    Code Why
    Versioned(value, ++clock) Each write carries a version, and reads pick the maximum. Real systems use per-key vector clocks or hybrid logical clocks, because one counter isn't available in a distributed cluster.
    for (int i : reachableOrder) ... if (++acks == w) return true The write succeeds once W replicas acknowledge. The rest are updated later (or not, as in the demo, which leaves r0 stale).
    if (v == null \|\| v.version() < newest.version()) { rep.data.put(key, newest); repairs.add(rep.name); } Read repair: the read path fixes the stale replicas it touched.
    N=3 W=1 R=1 → read v1 The read set {r0} and write set {r1} don't overlap, so the read is stale. It's the cost of the fastest settings.
    2 of 3 down: write ok? false With W=2, two failures make writes unavailable. That's the CAP trade-off in a single line.

    Complexity¶

    Approach Time Space
    write / read O(N) messages, waits for W / R N copies

    Solve it with Spring Boot 4¶

    A coordinator fans out every request to N replica services over HTTP with RestClient, on virtual threads, and answers as soon as W writes or R reads succeed within the timeout. Reads return the newest version and read-repair stale replicas. In the test, the replicas are real HTTP endpoints that can be taken down, so failures behave like separate nodes.

    sequenceDiagram participant C as Client participant Q as QuorumCoordinator participant A as replica a participant B as replica b participant R3 as replica c C->>Q: PUT /api/v1/kv/cart:42 {"3 items"} par fan-out (virtual threads) Q->>A: PUT v2 Q->>B: PUT v2 Q->>R3: PUT v2 end A-->>Q: 200 B-->>Q: 200 Q-->>C: 200 {acks: 2} (W reached; c's call continues in background) C->>Q: GET /api/v1/kv/cart:42 (a down) Q->>B: GET -> v2 Q->>R3: GET -> v1 (stale) Q->>R3: PUT v2 (read repair) Q-->>C: {"3 items", repaired: [c]}
    QuorumCoordinator.java
    package com.sdp.ci.p11quorum;

import com.sdp.ci.common.Problems;
import java.time.Clock;
import java.util.ArrayList;
import java.util.List;
import java.util.Optional;
import java.util.concurrent.*;
import java.util.concurrent.atomic.AtomicLong;
import org.springframework.http.HttpStatus;
import org.springframework.web.client.HttpClientErrorException;
import org.springframework.web.client.RestClient;

/**
 * Dynamo-style coordinator: fan out to all N replicas in parallel (virtual threads), succeed after W write
 * acks / R read replies within the timeout, return the newest version and repair stale replicas.
 */
public class QuorumCoordinator {
    public record WriteResult(long version, int acks, int required) {}
    public record ReadResult(String value, long version, int replies, int required, List<String> repaired) {}

    private final RestClient http;
    private final QuorumProperties props;
    private final Clock clock;
    private final AtomicLong lastVersion = new AtomicLong();
    private final java.util.concurrent.atomic.AtomicInteger inFlight = new java.util.concurrent.atomic.AtomicInteger();
    private final ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor();

    public QuorumCoordinator(RestClient http, QuorumProperties props, Clock clock) {
        this.http = http;
        this.props = props;
        this.clock = clock;
    }

    public WriteResult write(String key, String value) {
        long version = lastVersion.updateAndGet(prev -> Math.max(prev + 1, clock.millis()));   // monotonic per coordinator
        Versioned v = new Versioned(value, version);
        List<Callable<Boolean>> calls = props.replicas().stream()
                .map(url -> (Callable<Boolean>) () -> { put(url, key, v); return true; }).toList();
        int acks = awaitSuccesses(calls, props.w()).size();
        if (acks < props.w()) {
            // Some replicas may still have the value: the client must retry (idempotent thanks to the version).
            throw Problems.of(HttpStatus.SERVICE_UNAVAILABLE, "write quorum not met: " + acks + "/" + props.w() + " acks");
        }
        return new WriteResult(version, acks, props.w());
    }

    public ReadResult read(String key) {
        List<String> urls = props.replicas();
        List<Callable<Reply>> calls = urls.stream().map(url -> (Callable<Reply>) () -> new Reply(url, get(url, key))).toList();
        List<Reply> replies = awaitSuccesses(calls, props.r());
        if (replies.size() < props.r()) {
            throw Problems.of(HttpStatus.SERVICE_UNAVAILABLE, "read quorum not met: " + replies.size() + "/" + props.r() + " replies");
        }
        Versioned newest = replies.stream().map(Reply::value).flatMap(Optional::stream)
                .max(java.util.Comparator.comparingLong(Versioned::version)).orElse(null);
        List<String> repaired = new ArrayList<>();
        if (newest != null) {
            for (Reply r : replies) {                        // read repair: push the newest value to stale repliers
                if (r.value().map(Versioned::version).orElse(-1L) < newest.version()) {
                    put(r.url(), key, newest);
                    repaired.add(r.url().substring(r.url().lastIndexOf('/') + 1));
                }
            }
        }
        return new ReadResult(newest == null ? null : newest.value(), newest == null ? 0 : newest.version(),
                replies.size(), props.r(), repaired);
    }

    /** Run all calls in parallel; return the results that succeed, stopping early once `needed` have succeeded. */
    private <T> List<T> awaitSuccesses(List<Callable<T>> calls, int needed) {
        CompletionService<T> cs = new ExecutorCompletionService<>(pool);
        List<Future<T>> futures = calls.stream().map(cs::submit).toList();
        List<T> ok = new ArrayList<>();
        long deadline = System.nanoTime() + props.timeout().toNanos();
        try {
            for (int done = 0; done < calls.size() && ok.size() < needed; done++) {
                Future<T> f = cs.poll(Math.max(0, deadline - System.nanoTime()), TimeUnit.NANOSECONDS);
                if (f == null) break;                                         // timed out
                try { ok.add(f.get()); } catch (ExecutionException failedReplica) { /* counts as no reply */ }
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        return ok;
    }

    private record Reply(String url, Optional<Versioned> value) {}

    /**
     * Replica calls still running. A write returns after W acks, but the remaining N - W requests keep going
     * in the background and may land later, which is how lagging replicas still converge. Worth exporting as a gauge.
     */
    public int inFlight() { return inFlight.get(); }

    private void put(String url, String key, Versioned v) {
        inFlight.incrementAndGet();
        try {
            http.put().uri(url + "/kv/{key}", key).body(v).retrieve().toBodilessEntity();
        } finally { inFlight.decrementAndGet(); }
    }

    private Optional<Versioned> get(String url, String key) {
        inFlight.incrementAndGet();
        try {
            return Optional.ofNullable(http.get().uri(url + "/kv/{key}", key).retrieve().body(Versioned.class));
        } catch (HttpClientErrorException.NotFound e) {
            return Optional.empty();                                          // a valid reply: "I don't have it"
        } finally { inFlight.decrementAndGet(); }
    }
}
    ReplicaNodeController.java
    package com.sdp.ci.p11quorum;

import com.sdp.ci.common.Problems;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

/**
 * The storage-node side. In production every replica is a separate service; here one app hosts nodes a/b/c
 * on different paths so a single process can show real HTTP fan-out, timeouts and failures.
 */
@RestController
@RequestMapping("/internal/replicas/{node}")
public class ReplicaNodeController {
    private final Map<String, Map<String, Versioned>> data = new ConcurrentHashMap<>();
    private final Map<String, Boolean> down = new ConcurrentHashMap<>();

    @GetMapping("/kv/{key}")
    public ResponseEntity<Versioned> get(@PathVariable String node, @PathVariable String key) {
        failIfDown(node);
        Versioned v = store(node).get(key);
        return v == null ? ResponseEntity.notFound().build() : ResponseEntity.ok(v);
    }

    /** Only accept newer versions, so retries and read repair are idempotent. */
    @PutMapping("/kv/{key}")
    public Versioned put(@PathVariable String node, @PathVariable String key, @RequestBody Versioned value) {
        failIfDown(node);
        return store(node).merge(key, value, (old, neu) -> neu.version() >= old.version() ? neu : old);
    }

    /** Failure injection for demos and tests. */
    @PutMapping("/down")
    public void setDown(@PathVariable String node, @RequestParam boolean value) { down.put(node, value); }

    private Map<String, Versioned> store(String node) { return data.computeIfAbsent(node, n -> new ConcurrentHashMap<>()); }

    private void failIfDown(String node) {
        if (down.getOrDefault(node, false)) throw Problems.of(HttpStatus.SERVICE_UNAVAILABLE, "replica " + node + " is down");
    }
}
    QuorumProperties.java
    package com.sdp.ci.p11quorum;

import java.time.Duration;
import java.util.List;
import org.springframework.boot.context.properties.ConfigurationProperties;

/** N replicas, write quorum W, read quorum R. R + W > N guarantees a read overlaps the latest write. */
@ConfigurationProperties("ci.quorum")
public record QuorumProperties(int n, int w, int r, Duration timeout, List<String> replicas) {
    public QuorumProperties {
        if (replicas == null || replicas.size() != n) throw new IllegalArgumentException("need exactly n replica URLs");
        if (w < 1 || r < 1 || w > n || r > n) throw new IllegalArgumentException("1 <= w, r <= n");
    }

    public boolean strong() { return r + w > n; }
}
    QuorumConfig.java
    package com.sdp.ci.p11quorum;

import java.time.Clock;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.client.JdkClientHttpRequestFactory;
import org.springframework.web.client.RestClient;

@Configuration(proxyBeanMethods = false)
public class QuorumConfig {
    @Bean
    QuorumCoordinator quorumCoordinator(RestClient.Builder builder, QuorumProperties props, Clock clock) {
        var http = java.net.http.HttpClient.newBuilder().connectTimeout(props.timeout()).build();
        var factory = new JdkClientHttpRequestFactory(http);
        factory.setReadTimeout(props.timeout());          // a slow replica must not hold the request
        return new QuorumCoordinator(builder.requestFactory(factory).build(), props, clock);
    }
}

    What changes from the interview version¶

    Interview Production (Spring Boot 4)
    replicas are objects in a list separate services called over HTTP with connect/read timeouts
    sequential calls parallel fan-out on virtual threads; return at W/R successes, don't wait for the slowest replica
    version counter per-coordinator monotonic version (LWW). Real systems use vector clocks or hybrid logical clocks
    failure = exception 503 ProblemDetail "write quorum not met" (safe to retry: the replica only accepts newer versions)
    validated in code QuorumProperties rejects invalid N/W/R at startup

    Two things the test exposed (see the Spring Boot overview): a 200 ms timeout fails on a cold JVM, and the N − W calls still in flight can update a "stale" replica after the coordinator has answered. Missing pieces you should name: hinted handoff for writes to down nodes, and sloppy quorums.

    Common mistakes¶

    • Thinking R + W > N gives linearizability. It doesn't on its own: concurrent writes, sloppy quorums and clock-based versions can still misbehave.
    • Last-write-wins with wall-clock timestamps, which silently drops concurrent updates. Use vector clocks plus application merge, or CRDTs.
    • Forgetting that a failed quorum write may still have reached some replicas, so it may appear later. Clients must treat a failed write as "unknown", not "didn't happen".

    Follow-up questions¶

    Sloppy quorum and hinted handoff?

    If home replicas are down, a sloppy quorum writes to other healthy nodes, which keep a hint and hand the data back when the home replica returns. Availability goes up, but R + W > N no longer guarantees overlap with the home replicas.

    How do Cassandra's consistency levels map to this?

    ONE, QUORUM, ALL per query, plus LOCAL_QUORUM (a quorum within one data centre) for multi-region setups. A common choice is LOCAL_QUORUM for both reads and writes with RF = 3, which gives strong consistency within a DC and survives one node failure.
