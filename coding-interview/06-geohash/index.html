    6. Geohash: "Restaurants Near Me"¶

    L3 ★★★ · Bit interleaving, base32, neighbour cells, haversine filter

    Problem¶

    Given restaurant locations, find those within 1 km of a user. Encode coordinates so that nearby points share a key prefix and can be indexed with an ordinary B-tree or hash. Handle points just across a cell boundary.

    Key idea¶

    Geohash repeatedly bisects longitude and latitude alternately, one bit per step, and writes the bits in base32. Points that share a prefix are in the same cell (6 characters ≈ 1.2 km × 0.6 km). Two nearby points can sit on opposite sides of a boundary and share no prefix, so search the user's cell plus its 8 neighbours, then filter by real distance (haversine).

    flowchart TB subgraph grid["search area: 3 × 3 cells at precision 6"] direction LR a[tdr1v8] --- b[tdr1vb] --- c[tdr1vc] d[tdr1v2] --- e["tdr1v9 (me)"] --- f[tdr1vd] g[tdr1v3] --- h[tdr1v6] --- i[tdr1vf] end grid --> HV["haversine ≤ 1 km → Cafe A, Diner B"]

    Solution¶

    Geohash.java
    import java.util.*;

/** Problem: "restaurants near me": encode lat/lon so that nearby points share a prefix; search the cell + its 8 neighbours. */
public class Geohash {

    private static final String BASE32 = "0123456789bcdefghjkmnpqrstuvwxyz";

    /** Interleave longitude and latitude bisection bits (lon first), 5 bits per base32 char. */
    static String encode(double lat, double lon, int precision) {
        double[] latR = {-90, 90}, lonR = {-180, 180};
        StringBuilder hash = new StringBuilder();
        boolean even = true; int bit = 0, ch = 0;
        while (hash.length() < precision) {
            double[] r = even ? lonR : latR;
            double v = even ? lon : lat, mid = (r[0] + r[1]) / 2;
            if (v >= mid) { ch = (ch << 1) | 1; r[0] = mid; } else { ch <<= 1; r[1] = mid; }
            even = !even;
            if (++bit == 5) { hash.append(BASE32.charAt(ch)); bit = 0; ch = 0; }
        }
        return hash.toString();
    }

    /** Decode to the cell's bounding box: [minLat, maxLat, minLon, maxLon]. */
    static double[] bounds(String hash) {
        double[] latR = {-90, 90}, lonR = {-180, 180};
        boolean even = true;
        for (char c : hash.toCharArray()) {
            int cd = BASE32.indexOf(c);
            for (int mask = 16; mask > 0; mask >>= 1) {
                double[] r = even ? lonR : latR;
                double mid = (r[0] + r[1]) / 2;
                if ((cd & mask) != 0) r[0] = mid; else r[1] = mid;
                even = !even;
            }
        }
        return new double[]{latR[0], latR[1], lonR[0], lonR[1]};
    }

    /** Neighbours by stepping one cell height/width from the centre (robust, avoids lookup tables). */
    static Set<String> cellAndNeighbours(String hash) {
        double[] b = bounds(hash);
        double h = b[1] - b[0], w = b[3] - b[2], lat = (b[0] + b[1]) / 2, lon = (b[2] + b[3]) / 2;
        Set<String> out = new TreeSet<>();
        for (int dy = -1; dy <= 1; dy++) for (int dx = -1; dx <= 1; dx++) {
            double nlat = Math.max(-89.999999, Math.min(89.999999, lat + dy * h));
            double nlon = ((lon + dx * w + 540) % 360) - 180;          // wrap the antimeridian
            out.add(encode(nlat, nlon, hash.length()));
        }
        return out;
    }

    static double km(double lat1, double lon1, double lat2, double lon2) {   // haversine
        double dLat = Math.toRadians(lat2 - lat1), dLon = Math.toRadians(lon2 - lon1);
        double a = Math.pow(Math.sin(dLat / 2), 2) + Math.cos(Math.toRadians(lat1)) * Math.cos(Math.toRadians(lat2)) * Math.pow(Math.sin(dLon / 2), 2);
        return 6371 * 2 * Math.asin(Math.sqrt(a));
    }

    record Place(String name, double lat, double lon) { }

    public static void main(String[] args) {
        double meLat = 12.9716, meLon = 77.5946;                       // Bengaluru
        List<Place> places = List.of(new Place("Cafe A", 12.9721, 77.5933), new Place("Diner B", 12.9690, 77.6010),
                new Place("Bistro C", 12.9352, 77.6245), new Place("Mumbai D", 19.0760, 72.8777));

        int precision = 6;                                              // ~1.2 km x 0.6 km cells
        String mine = encode(meLat, meLon, precision);
        Set<String> searchCells = cellAndNeighbours(mine);
        System.out.println("my geohash (p=6) = " + mine + ", search cells = " + searchCells);

        Map<String, List<Place>> index = new HashMap<>();             // production: geohash column with a B-tree index, or Redis GEO
        for (Place p : places) index.computeIfAbsent(encode(p.lat(), p.lon(), precision), x -> new ArrayList<>()).add(p);

        List<String> found = new ArrayList<>();
        for (String cell : searchCells)
            for (Place p : index.getOrDefault(cell, List.of()))
                if (km(meLat, meLon, p.lat(), p.lon()) <= 1.0) found.add(String.format("%s (%.2f km)", p.name(), km(meLat, meLon, p.lat(), p.lon())));
        Collections.sort(found);
        System.out.println("within 1 km: " + found);
        System.out.println("shared prefix of two nearby points: " + encode(12.9716, 77.5946, 7) + " vs " + encode(12.9721, 77.5933, 7));
        check(found.size() == 2 && found.get(0).startsWith("Cafe A"), "nearby found, far filtered");
        check(searchCells.size() == 9, "cell + 8 neighbours");
        check(encode(57.64911, 10.40744, 11).equals("u4pruydqqvj"), "matches the reference geohash");
        System.out.println("PASS");
    }

    static void check(boolean ok, String what) { if (!ok) { System.out.println("FAILED: " + what); System.exit(1); } }
}

    Walkthrough¶

    Code Why
    if (v >= mid) { ch = (ch << 1) \| 1; r[0] = mid; } else { ch <<= 1; r[1] = mid; } Each bit halves the current range. Even bits are longitude, odd bits latitude.
    if (++bit == 5) { hash.append(BASE32.charAt(ch)); ... } Every 5 bits become one base32 character (no a, i, l, o).
    cellAndNeighbours: step ± one cell height/width from the centre Computing neighbours by re-encoding offset points is simple and handles wrap-around. Lookup tables are faster but error-prone.
    ((lon + dx * w + 540) % 360) - 180 Wrap across the ±180° antimeridian.
    encode(57.64911, 10.40744, 11).equals("u4pruydqqvj") Checked against the reference example from the geohash spec.

    Complexity¶

    Approach Time Space
    encode O(precision) O(1)
    nearby search 9 index lookups + O(candidates) -

    Solve it with Spring Boot 4¶

    Redis GEO is the interview structure ready-made: a sorted set scored by a 52-bit interleaved geohash. GEOSEARCH scans the centre cell and its neighbours, then filters by true distance, which is the same algorithm as the solution above.

    sequenceDiagram participant C as Client participant G as RestaurantGeoController participant S as RestaurantGeoService participant R as Redis GEO C->>G: PUT /api/v1/restaurants/{id}/location {lat, lon} G->>S: upsert -> GEOADD geo:restaurants lon lat id C->>G: GET /api/v1/restaurants/near?lat&lon&km=3 G->>S: near(...) S->>R: GEOSEARCH FROMLONLAT lon lat BYRADIUS 3 km ASC COUNT 5 WITHDIST S->>R: GEOHASH (for display) S-->>C: [{id, km, geohash}] nearest first
    RestaurantGeoService.java
    package com.sdp.ci.p06geo;

import java.util.List;
import org.springframework.data.geo.Distance;
import org.springframework.data.geo.Metrics;
import org.springframework.data.geo.Point;
import org.springframework.data.redis.connection.RedisGeoCommands.GeoLocation;
import org.springframework.data.redis.connection.RedisGeoCommands.GeoSearchCommandArgs;
import org.springframework.data.redis.domain.geo.GeoReference;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

/**
 * Redis GEO is a sorted set scored by a 52-bit interleaved geohash: exactly the interview structure.
 * GEOSEARCH scans the centre cell + neighbours and filters by true (haversine) distance for you.
 */
@Service
public class RestaurantGeoService {
    public record Nearby(String id, double km, String geohash) {}

    static final String KEY = "geo:restaurants";
    private final StringRedisTemplate redis;

    public RestaurantGeoService(StringRedisTemplate redis) { this.redis = redis; }

    public void upsert(String id, double lat, double lon) {
        redis.opsForGeo().add(KEY, new Point(lon, lat), id);          // note: Redis takes (longitude, latitude)
    }

    public List<Nearby> near(double lat, double lon, double radiusKm, int limit) {
        var results = redis.opsForGeo().search(KEY,
                GeoReference.fromCoordinate(lon, lat),
                new Distance(radiusKm, Metrics.KILOMETERS),
                GeoSearchCommandArgs.newGeoSearchArgs().includeDistance().sortAscending().limit(limit));
        if (results == null) return List.of();
        List<String> ids = results.getContent().stream().map(r -> r.getContent().getName()).toList();
        List<String> hashes = ids.isEmpty() ? List.of() : redis.opsForGeo().hash(KEY, ids.toArray(String[]::new));
        return java.util.stream.IntStream.range(0, ids.size())
                .mapToObj(i -> new Nearby(ids.get(i), Math.round(results.getContent().get(i).getDistance().getValue() * 100) / 100.0, hashes.get(i)))
                .toList();
    }
}
    RestaurantGeoController.java
    package com.sdp.ci.p06geo;

import jakarta.validation.constraints.DecimalMax;
import jakarta.validation.constraints.DecimalMin;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Positive;
import java.util.List;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/v1/restaurants")
public class RestaurantGeoController {
    public record Location(@DecimalMin("-90") @DecimalMax("90") double lat, @DecimalMin("-180") @DecimalMax("180") double lon) {}

    private final RestaurantGeoService geo;

    public RestaurantGeoController(RestaurantGeoService geo) { this.geo = geo; }

    @PutMapping("/{id}/location")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void move(@PathVariable String id, @RequestBody @jakarta.validation.Valid Location loc) { geo.upsert(id, loc.lat(), loc.lon()); }

    @GetMapping("/near")
    public List<RestaurantGeoService.Nearby> near(@RequestParam @DecimalMin("-90") @DecimalMax("90") double lat,
                                                  @RequestParam @DecimalMin("-180") @DecimalMax("180") double lon,
                                                  @RequestParam(defaultValue = "3") @Positive @Max(50) double km,
                                                  @RequestParam(defaultValue = "10") @Positive @Max(100) int limit) {
        return geo.near(lat, lon, km, limit);
    }
}

    What changes from the interview version¶

    Interview Production (Spring Boot 4)
    encode + 9 neighbour cells + haversine filter GEOSEARCH ... BYRADIUS does all three server-side
    in-memory list Redis sorted set: O(log n) moves when a restaurant (or a rider) updates its location
    no validation @DecimalMin/@DecimalMax on lat/lon via MVC method validation, giving a 400 ProblemDetail

    The geohashes in the output (tdr1v… and tdr1t…) share the prefix tdr1: nearby places share prefixes, which is the property that makes geohash work. For polygons ("delivers to this zone") or ranking by more than distance, move to PostGIS or Elasticsearch geo_shape.

    Common mistakes¶

    • Searching only the user's own cell, which misses places 10 m away across the boundary.
    • Choosing the precision without considering the radius. The cell must be at least as large as the search radius, or 9 cells won't cover it.
    • Comparing distances in degrees. One degree of longitude shrinks with latitude, so use haversine.
    • Hot cells in dense cities. Split adaptively (quadtree) or use precision that varies with density.

    Follow-up questions¶

    Geohash vs quadtree vs S2/H3?

    Geohash is a string prefix that works with any key-value store or B-tree, but its cells are rectangles that are distorted near the poles. A quadtree adapts to density (it splits busy areas) but is an in-memory structure. S2 (Google) and H3 (Uber) use spherical or hexagonal cells with uniform neighbours, which is better for ride-hailing and analytics.

    How would you do this in PostGIS or Redis?

    PostGIS: a geography column, a GiST index, and ST_DWithin(location, me, 1000). Redis: GEOADD, then GEOSEARCH ... BYRADIUS 1 km. Internally it's a 52-bit geohash stored as a sorted-set score.
