    8. Leaderboard: Ranks, Top-N, Neighbours¶

    L2 ★★☆ · Ordered set, Fenwick tree for ranks, Redis sorted-set semantics

    Problem¶

    Build a game leaderboard with 10,000+ players: increment a score, get a player's rank, the top N, and the players around a given player. Ties are broken deterministically. These are the operations of a Redis sorted set.

    Key idea¶

    An ordered set of (score desc, name) gives top-N and neighbours by walking from a position. Rank needs "how many are ahead of me?". Walking the set is O(n), so keep a Fenwick (binary indexed) tree of counts per score for O(log S) prefix sums. Redis does this with a skip list whose links carry span counts.

    flowchart LR U["ZINCRBY bob +49995"] --> RM["remove (bob, 50000)"] --> AD["add (bob, 99995)"] --> FW["Fenwick: -1 at 50000, +1 at 99995"] Q["ZREVRANK cara"] --> C["count(score > 50000) via Fenwick"] --> T["+ ties ordered before cara"] --> R["rank 4982"]

    Solution¶

    Leaderboard.java
    import java.util.*;

/** Problem: game leaderboard: update scores, get a player's rank, top-N, and players around me (Redis ZSET semantics). */
public class Leaderboard {

    record Entry(String player, long score) { }

    /** Order: higher score first; ties -> earlier player name (deterministic). */
    private static final Comparator<Entry> ORDER = Comparator.comparingLong(Entry::score).reversed().thenComparing(Entry::player);

    private final TreeSet<Entry> ranking = new TreeSet<>(ORDER);
    private final Map<String, Long> scores = new HashMap<>();
    // Fenwick tree over score buckets for O(log S) rank queries without walking the TreeSet
    private static final int MAX_SCORE = 1_000_000;
    private final long[] fenwick = new long[MAX_SCORE + 2];

    void addScore(String player, long delta) {                                  // ZINCRBY
        Long old = scores.get(player);
        long now = (old == null ? 0 : old) + delta;
        if (now < 0 || now > MAX_SCORE) throw new IllegalArgumentException("score out of range");
        if (old != null) { ranking.remove(new Entry(player, old)); fenwickAdd(old, -1); }
        ranking.add(new Entry(player, now));
        fenwickAdd(now, 1);
        scores.put(player, now);
    }

    /** 1-based rank = 1 + players with a higher score + players with the same score and a smaller name. */
    int rank(String player) {                                                   // ZREVRANK + 1
        long s = scores.get(player);
        long higher = countAtMost(MAX_SCORE) - countAtMost(s);
        long tiesBefore = ranking.subSet(new Entry("", s), true, new Entry(player, s), false).size();
        return (int) (higher + tiesBefore + 1);
    }

    List<Entry> top(int n) { return ranking.stream().limit(n).toList(); }       // ZREVRANGE 0 n-1

    List<Entry> around(String player, int radius) {
        Entry me = new Entry(player, scores.get(player));
        List<Entry> above = new ArrayList<>(ranking.headSet(me, false).descendingSet().stream().limit(radius).toList());
        Collections.reverse(above);
        List<Entry> out = new ArrayList<>(above);
        out.add(me);
        out.addAll(ranking.tailSet(me, false).stream().limit(radius).toList());
        return out;
    }

    private void fenwickAdd(long score, int d) { for (int i = (int) score + 1; i < fenwick.length; i += i & -i) fenwick[i] += d; }
    private long countAtMost(long score) { long c = 0; for (int i = (int) score + 1; i > 0; i -= i & -i) c += fenwick[i]; return c; }

    public static void main(String[] args) {
        Leaderboard lb = new Leaderboard();
        Random r = new Random(3);
        for (int i = 0; i < 10_000; i++) lb.addScore("p" + i, r.nextInt(100_000));
        lb.addScore("ana", 99_990);
        lb.addScore("bob", 50_000);
        lb.addScore("bob", 49_995);        // bob climbs to 99,995
        lb.addScore("cara", 50_000);       // a mid-table player

        System.out.println("top 3       = " + lb.top(3));
        System.out.println("rank(bob)   = " + lb.rank("bob") + ", rank(ana) = " + lb.rank("ana"));
        System.out.println("rank(cara)  = " + lb.rank("cara"));
        System.out.println("around(cara)= " + lb.around("cara", 2));

        List<Entry> all = lb.ranking.stream().toList();
        check(all.get(lb.rank("ana") - 1).player().equals("ana"), "Fenwick rank matches the ordered set");
        check(all.get(lb.rank("bob") - 1).player().equals("bob") && lb.rank("bob") < lb.rank("ana"), "update reorders");
        check(lb.around("cara", 2).size() == 5 && lb.around("cara", 2).get(2).player().equals("cara"), "neighbourhood");
        check(all.get(lb.rank("cara") - 1).player().equals("cara"), "rank of a mid-table player");
        System.out.println("PASS");
    }

    static void check(boolean ok, String what) { if (!ok) { System.out.println("FAILED: " + what); System.exit(1); } }
}

    Walkthrough¶

    Code Why
    Comparator.comparingLong(Entry::score).reversed().thenComparing(Entry::player) A total order, which a TreeSet needs. Without the tie-break, equal scores would be treated as duplicates and dropped.
    ranking.remove(new Entry(player, old)); ... ranking.add(new Entry(player, now)) To update an ordered element, remove it with its old key and re-insert it. Mutating a key inside a TreeSet corrupts the set.
    countAtMost(MAX_SCORE) - countAtMost(s) Players with a strictly higher score, using two O(log S) Fenwick prefix sums.
    ranking.headSet(me, false).descendingSet().stream().limit(radius) The neighbours above, nearest first. tailSet gives the ones below.
    check(all.get(rank - 1).player().equals(...)) The fast rank is cross-checked against the position in the fully ordered list.

    Complexity¶

    Approach Time Space
    update O(log n + log S) O(n + S)
    rank O(log S) + ties -
    top-N / around O(log n + N) -

    Run it¶

    java coding-interview/src/Leaderboard.java      # JDK 21+ single-file launcher, no build needed

    top 3       = [Entry[player=bob, score=99995], Entry[player=ana, score=99990], Entry[player=p9784, score=99986]]
rank(bob)   = 1, rank(ana) = 2
rank(cara)  = 4982
around(cara)= [Entry[player=p437, score=50010], Entry[player=p2780, score=50007], Entry[player=cara, score=50000], Entry[player=p9050, score=49991], Entry[player=p6771, score=49982]]
PASS

    Common mistakes¶

    • Sorting the whole list on every query (O(n log n)), which falls over at millions of players.
    • Leaving ties ambiguous, so ranks jump around between refreshes.
    • Changing a score in place inside the ordered structure.
    • A single global sorted set for 100M players. Shard by region or league, and compute global top-N by merging the shards' top-Ns.

    Follow-up questions¶

    How do you get the rank of a player among 500 million?

    An exact rank needs a global ordered index. Shard by score range (each shard knows its count, so rank = counts of higher shards + local rank), or use approximate ranks from a score histogram, which is often enough when you show "top 3%".

    Daily, weekly and all-time boards?

    Keep separate sorted sets per period (lb:2025-01-01) with TTLs. Use ZUNIONSTORE to build the weekly board from the daily ones, or update all three on each score event.
