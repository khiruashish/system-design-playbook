    7. Trending Top-K: Count-Min Sketch + Heap¶

    L3 ★★★ · Count-Min Sketch, error bounds, streaming top-K

    Problem¶

    Find the top 5 trending hashtags in a stream of 315,000 events with about 50,000 distinct tags, using fixed memory that doesn't grow with the number of distinct tags. Prove the estimates stay within the theoretical error bound.

    Key idea¶

    A Count-Min Sketch is a d × w grid of counters. Each item increments one counter per row; the estimate is the minimum across rows. It never underestimates, and overestimates by at most ε·N with probability 1 − δ (w = e/ε, d = ln(1/δ)). Pair it with a size-K candidate set: after each update, an item enters if its estimate beats the weakest member.

    flowchart LR T["#ai"] --> R1["row 1: h1 → +1"] T --> R2["row 2: h2 → +1"] T --> R3["row 3: h3 → +1"] R1 & R2 & R3 --> MIN["estimate = min(row counters)"] MIN --> K{"beats weakest of top-5?"} K -->|yes| HEAP[replace in top-K]

    Solution¶

    HeavyHitters.java
    import java.util.*;

/** Problem: top-K trending hashtags over a huge stream in fixed memory: Count-Min Sketch + a size-K min-heap. */
public class HeavyHitters {

    /** d rows x w counters. Estimate = min over rows: never underestimates, overestimates by <= eps*N with prob 1-delta. */
    static final class CountMinSketch {
        private final int width, depth;
        private final long[][] table;
        private final long[] seeds;
        private long total;

        CountMinSketch(double epsilon, double delta) {
            this.width = (int) Math.ceil(Math.E / epsilon);
            this.depth = (int) Math.ceil(Math.log(1 / delta));
            this.table = new long[depth][width];
            this.seeds = new long[depth];
            Random r = new Random(17);
            for (int i = 0; i < depth; i++) seeds[i] = r.nextLong() | 1;
        }

        private int bucket(String item, int row) {
            long h = item.hashCode() * seeds[row];
            h ^= h >>> 31; h *= 0x9E3779B97F4A7C15L; h ^= h >>> 29;
            return (int) Math.floorMod(h, (long) width);
        }

        void add(String item) { total++; for (int r = 0; r < depth; r++) table[r][bucket(item, r)]++; }

        long estimate(String item) {
            long min = Long.MAX_VALUE;
            for (int r = 0; r < depth; r++) min = Math.min(min, table[r][bucket(item, r)]);
            return min;
        }

        long counters() { return (long) width * depth; }
        long total() { return total; }
    }

    /** Keep the current top K by estimated count. Heap of (item) ordered by estimate; a map tracks membership. */
    static final class TopK {
        private final int k;
        private final CountMinSketch cms;
        private final Map<String, Long> members = new HashMap<>();
        TopK(int k, CountMinSketch cms) { this.k = k; this.cms = cms; }

        void offer(String item) {
            cms.add(item);
            long est = cms.estimate(item);
            if (members.containsKey(item) || members.size() < k) { members.put(item, est); return; }
            String weakest = Collections.min(members.entrySet(), Map.Entry.comparingByValue()).getKey();   // O(k); fine for small k
            if (est > members.get(weakest)) { members.remove(weakest); members.put(item, est); }
        }

        List<Map.Entry<String, Long>> top() {
            List<Map.Entry<String, Long>> list = new ArrayList<>(members.entrySet());
            list.sort(Map.Entry.<String, Long>comparingByValue().reversed().thenComparing(Map.Entry.comparingByKey()));
            return list;
        }
    }

    public static void main(String[] args) {
        // Zipf-like stream: #tag0 most popular, long tail of 50,000 rare tags
        Random r = new Random(1);
        List<String> stream = new ArrayList<>();
        String[] trending = {"#worldcup", "#election", "#ai", "#budget", "#monsoon"};
        int[] weights = {50_000, 30_000, 20_000, 10_000, 5_000};
        for (int i = 0; i < trending.length; i++) for (int j = 0; j < weights[i]; j++) stream.add(trending[i]);
        for (int i = 0; i < 200_000; i++) stream.add("#tail" + r.nextInt(50_000));
        Collections.shuffle(stream, r);

        CountMinSketch cms = new CountMinSketch(0.0005, 0.001);
        TopK top = new TopK(5, cms);
        Map<String, Integer> exact = new HashMap<>();
        for (String tag : stream) { top.offer(tag); exact.merge(tag, 1, Integer::sum); }

        System.out.printf("stream=%d events, distinct=%d; sketch uses %d counters (%.0f KB) vs exact map of %d keys%n",
                cms.total(), exact.size(), cms.counters(), cms.counters() * 8 / 1024.0, exact.size());
        for (var e : top.top()) System.out.printf("  %-10s estimate=%d exact=%d%n", e.getKey(), e.getValue(), exact.get(e.getKey()));
        List<String> names = top.top().stream().map(Map.Entry::getKey).toList();
        check(names.equals(List.of(trending)), "top 5 identified in order");
        for (String t : trending) check(cms.estimate(t) >= exact.get(t) && cms.estimate(t) - exact.get(t) <= 0.0005 * cms.total(), "error bound for " + t);
        System.out.println("PASS");
    }

    static void check(boolean ok, String what) { if (!ok) { System.out.println("FAILED: " + what); System.exit(1); } }
}

    Walkthrough¶

    Code Why
    width = ceil(e / epsilon); depth = ceil(ln(1 / delta)) ε = 0.0005 and δ = 0.001 give 5,437 × 7 counters, independent of the number of distinct items.
    min over rows Collisions only ever add counts, so the smallest counter is the tightest upper bound.
    if (members.containsKey(item) \|\| members.size() < k) ... else replace weakest Candidate tracking. The O(k) scan is fine for small k; use a heap with an index map for large k.
    check(estimate - exact <= 0.0005 * total) The test asserts the ε·N bound for every trending tag. The output shows +12 to +35 on counts of thousands.

    Complexity¶

    Approach Time Space
    update O(d) O(d·w) counters, fixed
    top-K maintenance O(k) per update here (O(log k) with an indexed heap) O(k)

    Solve it with Spring Boot 4¶

    The sketch lives in a Redis hash per hourly window (row:col → count) and a top-K sorted set beside it. One Lua call increments the d counters, takes the minimum as the estimate, and updates the top-K, all atomically. Old windows expire on their own.

    sequenceDiagram participant E as View events (Kafka consumer / API) participant T as TrendingService participant R as Redis (cms-topk.lua) participant C as Client E->>T: record("product-7") T->>R: HINCRBY cms:{hour} r:c x5, min -> estimate, ZADD topk:{hour}, trim to K C->>T: GET /api/v1/trending?k=5 T->>R: ZREVRANGE topk:{hour} 0 4 WITHSCORES T-->>C: [{item, estimate}]
    cms-topk.lua
    -- Count-Min Sketch + top-K in one atomic call.
-- KEYS[1] = sketch hash (field "row:col"), KEYS[2] = top-K sorted set
-- ARGV: item, k, ttl_ms, col_row0, col_row1, ...
local estimate = nil
for i = 4, #ARGV do
  local v = redis.call('HINCRBY', KEYS[1], (i - 4) .. ':' .. ARGV[i], 1)
  if estimate == nil or v < estimate then estimate = v end         -- CMS estimate = min over rows
end
redis.call('ZADD', KEYS[2], estimate, ARGV[1])
local k, size = tonumber(ARGV[2]), redis.call('ZCARD', KEYS[2])
if size > k then redis.call('ZREMRANGEBYRANK', KEYS[2], 0, size - k - 1) end   -- keep only the K largest
redis.call('PEXPIRE', KEYS[1], ARGV[3])
redis.call('PEXPIRE', KEYS[2], ARGV[3])
return estimate
    TrendingService.java
    package com.sdp.ci.p07trending;

import java.nio.charset.StandardCharsets;
import java.time.Clock;
import java.time.Duration;
import java.util.ArrayList;
import java.util.List;
import org.springframework.core.io.ClassPathResource;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.data.redis.core.ZSetOperations.TypedTuple;
import org.springframework.data.redis.core.script.RedisScript;
import org.springframework.stereotype.Service;

/**
 * "Trending in the last hour": a Count-Min Sketch (fixed memory, never undercounts) plus a top-K sorted set,
 * kept per hourly window in Redis. Width w and depth d give error <= (e / w) * N with probability 1 - e^-d.
 */
@Service
public class TrendingService {
    public record Trend(String item, long estimate) {}

    static final int WIDTH = 2_000, DEPTH = 5, TOP_K = 10;
    private static final RedisScript<Long> RECORD = RedisScript.of(new ClassPathResource("scripts/cms-topk.lua"), Long.class);
    private static final Duration WINDOW = Duration.ofHours(1);

    private final StringRedisTemplate redis;
    private final Clock clock;

    public TrendingService(StringRedisTemplate redis, Clock clock) {
        this.redis = redis;
        this.clock = clock;
    }

    public long record(String item) {
        String window = currentWindow();
        List<Object> args = new ArrayList<>(List.of(item, String.valueOf(TOP_K), String.valueOf(WINDOW.multipliedBy(2).toMillis())));
        for (int row = 0; row < DEPTH; row++) args.add(String.valueOf(column(item, row)));
        return redis.execute(RECORD, List.of("cms:{" + window + "}", "topk:{" + window + "}"), args.toArray());
    }

    public List<Trend> top(int k) {
        var tuples = redis.opsForZSet().reverseRangeWithScores("topk:{" + currentWindow() + "}", 0, k - 1);
        if (tuples == null) return List.of();
        return tuples.stream().map((TypedTuple<String> t) -> new Trend(t.getValue(), t.getScore().longValue())).toList();
    }

    private String currentWindow() { return String.valueOf(clock.millis() / WINDOW.toMillis()); }

    /** Pairwise-independent-enough hash per row: seed the FNV-1a hash with the row number. */
    static int column(String item, int row) {
        long h = 0xcbf29ce484222325L ^ (row * 0x9E3779B97F4A7C15L);
        for (byte b : item.getBytes(StandardCharsets.UTF_8)) { h ^= (b & 0xff); h *= 0x100000001b3L; }
        h ^= (h >>> 33);
        return (int) Math.floorMod(h, (long) WIDTH);
    }
}
    TrendingController.java
    package com.sdp.ci.p07trending;

import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import java.util.List;
import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/api/v1/trending")
public class TrendingController {
    private final TrendingService trending;

    public TrendingController(TrendingService trending) { this.trending = trending; }

    /** In production this is fed by a Kafka consumer of view events rather than called per request. */
    @PostMapping("/{item}")
    @ResponseStatus(HttpStatus.ACCEPTED)
    public void view(@PathVariable String item) { trending.record(item); }

    @GetMapping
    public List<TrendingService.Trend> top(@RequestParam(defaultValue = "5") @Min(1) @Max(TrendingService.TOP_K) int k) {
        return trending.top(k);
    }
}

    What changes from the interview version¶

    Interview Production (Spring Boot 4)
    long[d][w] + PriorityQueue Redis hash (5 x 2,000 counters) + sorted set, shared by all consumers
    one stream forever per-hour windows with TTL; "last hour" = current window (or sum the last 2 for sliding)
    separate increment and heap update one Lua script: no lost updates between instances

    Measured: max overcount 3 against the bound e/w·N = 28, and the top 5 matched the exact counts. At very high event rates, pre-aggregate in the consumer (count locally for 1 s, then one HINCRBY per item) to cut Redis calls.

    Common mistakes¶

    • Using the sketch for rare items. The relative error is large when the true count is small compared with N.
    • Never decaying. "Trending" means recent, so use time-bucketed sketches (one per minute, summed over a window) or exponential decay.
    • Hashing with correlated functions across rows, which defeats the min-of-rows trick.

    Follow-up questions¶

    How would you compute trending over the last hour across many servers?

    Each server keeps per-minute sketches. Sketches are mergeable (cell-wise add), so a reducer sums the last 60 minutes from all servers, then picks the top-K from the merged candidates. This is a classic Flink or Kafka Streams job.

    Count-Min vs Space-Saving / Misra-Gries?

    Space-Saving keeps exactly k counters and directly gives heavy hitters with a guaranteed error, but it isn't as easily mergeable. Count-Min answers point queries for any item and merges trivially.
