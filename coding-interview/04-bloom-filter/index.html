    4. Bloom Filter: Sizing & Measured False Positives¶

    L2 ★★☆ · BitSet, optimal m and k, double hashing, no false negatives

    Problem¶

    Answer "has this username / URL / key been seen?" for 100k (or 1 billion) items in a fraction of the memory a set would use, with no false negatives and about 1% false positives. Size it from the target error rate and verify it empirically.

    Key idea¶

    Use m bits and k hash functions. add sets k bits; mightContain checks them, and if any is 0 the item is definitely absent. For n items and a target rate p: m = −n·ln p / (ln 2)², k = (m/n)·ln 2, which is about 9.6 bits and 7 hashes per item for 1%. Two base hashes simulate all k (h1 + i·h2, Kirsch–Mitzenmacher). It's used in front of databases (Cassandra, HBase, RocksDB SSTables) to skip disk reads for keys that are certainly absent.

    flowchart LR X["mightContain('user-42')"] --> H["h1 + i·h2 for i = 0..6"] H --> B["bits 13, 402, 77k, ... all 1?"] B -->|any 0| N[definitely NOT present → skip DB] B -->|all 1| Y[probably present → check DB]

    Solution¶

    BloomFilter.java
    import java.nio.charset.StandardCharsets;
import java.util.BitSet;

/** Problem: "has this username / URL been seen?" for a billion items in little memory, accepting rare false positives. */
public class BloomFilter {

    private final BitSet bits;
    private final int m;            // number of bits
    private final int k;            // number of hash functions

    /** Optimal sizing: m = -n ln p / (ln 2)^2,  k = (m/n) ln 2. */
    BloomFilter(long expectedItems, double falsePositiveRate) {
        this.m = (int) Math.ceil(-expectedItems * Math.log(falsePositiveRate) / (Math.log(2) * Math.log(2)));
        this.k = Math.max(1, (int) Math.round((double) m / expectedItems * Math.log(2)));
        this.bits = new BitSet(m);
    }

    void add(String item) { long[] h = hashes(item); for (int i = 0; i < k; i++) bits.set(index(h, i)); }

    /** false = definitely absent. true = probably present. */
    boolean mightContain(String item) {
        long[] h = hashes(item);
        for (int i = 0; i < k; i++) if (!bits.get(index(h, i))) return false;
        return true;
    }

    /** Kirsch–Mitzenmacher: two hashes simulate k: h_i = h1 + i*h2. */
    private int index(long[] h, int i) { return (int) Math.floorMod(h[0] + i * h[1], (long) m); }

    private static long[] hashes(String s) {
        byte[] data = s.getBytes(StandardCharsets.UTF_8);
        long h1 = 0xcbf29ce484222325L, h2 = 0x9E3779B97F4A7C15L;
        for (byte b : data) { h1 ^= b; h1 *= 0x100000001b3L; h2 = (h2 ^ b) * 0xff51afd7ed558ccdL; h2 ^= h2 >>> 33; }  // FNV-1a + a mix
        return new long[]{h1, h2 | 1};
    }

    int bitCount() { return m; }
    int hashCount() { return k; }

    public static void main(String[] args) {
        int n = 100_000;
        BloomFilter bf = new BloomFilter(n, 0.01);
        for (int i = 0; i < n; i++) bf.add("user-" + i);
        System.out.printf("n=%d, target p=1%% -> m=%d bits (%.1f KB, %.1f bits/item), k=%d hashes%n",
                n, bf.bitCount(), bf.bitCount() / 8192.0, (double) bf.bitCount() / n, bf.hashCount());

        boolean noFalseNegatives = true;
        for (int i = 0; i < n; i++) noFalseNegatives &= bf.mightContain("user-" + i);
        int falsePositives = 0, trials = 100_000;
        for (int i = 0; i < trials; i++) if (bf.mightContain("other-" + i)) falsePositives++;
        double fpr = 100.0 * falsePositives / trials;
        System.out.printf("false negatives: %s; measured false-positive rate on 100k unseen items: %.2f%%%n", noFalseNegatives ? "none" : "SOME", fpr);
        System.out.printf("a HashSet<String> of the same items would need roughly %d KB%n", n * 60 / 1024);
        check(noFalseNegatives, "never a false negative");
        check(fpr > 0.5 && fpr < 1.6, "FPR close to the 1% target");
        System.out.println("PASS");
    }

    static void check(boolean ok, String what) { if (!ok) { System.out.println("FAILED: " + what); System.exit(1); } }
}

    Walkthrough¶

    Code Why
    m = ceil(-n ln p / (ln 2)^2); k = round(m/n · ln 2) Size from requirements. The output shows 958,506 bits (117 KB) and k = 7 for 100k items at 1%.
    Math.floorMod(h[0] + i * h[1], (long) m) Double hashing: k indexes from 2 hashes, with no measurable loss in accuracy.
    return new long[]{h1, h2 \| 1} Forcing h2 to be odd avoids degenerate cases where h2 shares factors with m.
    measured false-positive rate ... 0.91% Measured against 100k unseen items, close to the 1% target. The test asserts the bound as well as printing it.

    Complexity¶

    Approach Time Space
    add / mightContain O(k) m bits ≈ 1.44 · n · log₂(1/p)

    Run it¶

    java coding-interview/src/BloomFilter.java      # JDK 21+ single-file launcher, no build needed

    n=100000, target p=1% -> m=958506 bits (117.0 KB, 9.6 bits/item), k=7 hashes
false negatives: none; measured false-positive rate on 100k unseen items: 0.91%
a HashSet<String> of the same items would need roughly 5859 KB
PASS

    Common mistakes¶

    • Expecting deletes to work. Clearing a bit can remove other items. Use a Counting Bloom filter or a Cuckoo filter.
    • Under-sizing. Inserting more than n items makes the FPR grow fast. Rebuild, or use a scalable Bloom filter.
    • Using String.hashCode() with k simple variants. Correlated hashes raise the FPR.

    Follow-up questions¶

    Where does a Bloom filter sit in a read path?

    In front of an expensive lookup that usually misses: per-SSTable filters in LSM databases, "username taken?" checks, crawler "URL already seen?" checks, CDN "is this object cached anywhere?" checks. A negative answer skips the I/O entirely.

    Bloom vs Cuckoo filter?

    Cuckoo filters support delete, have better lookup locality, and use less space at low FPRs (below about 3%). Inserts can fail when the table is nearly full. Bloom filters are simpler and their inserts never fail.
