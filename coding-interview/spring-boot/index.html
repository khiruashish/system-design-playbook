    Solving the Problems with Spring Boot 4¶

    The single-file solutions answer "code the core". The follow-up in a senior loop is usually "now ship it": where does the state live when you run 20 instances, what happens on a race between two servers, what does the API look like, how do you test it? This page and the "Solve it with Spring Boot 4" section on every problem page answer that with one real Spring Boot application in coding-interview/spring-boot.

    Every solution is an HTTP API backed by real Redis, covered by an integration test that runs against a real Redis server (no mocks), and the output shown on each page is that test's transcript, which CI regenerates and compares on every change.

    Stack¶

    Version / choice Why
    Spring Boot 4.1.2 (Spring Framework 7.0, Jackson 3) latest stable 4.x
    Java 21 (works on 25) virtual threads, records, pattern matching
    State Redis 7 via Spring Data Redis + Lettuce shared across instances; atomic Lua scripts
    Local cache Caffeine (W-TinyLFU) + the hand-written LFU as a Spring Cache
    HTTP client RestClient on the JDK HttpClient, with timeouts quorum fan-out
    Errors RFC 9457 ProblemDetail (spring.mvc.problemdetails.enabled) consistent 4xx/5xx bodies
    Validation Jakarta Bean Validation + Spring MVC method validation 400 on bad input
    Concurrency spring.threads.virtual.enabled=true, virtual-thread executors blocking code that scales
    Ops Actuator health/metrics, @Scheduled jobs

    Run it¶

    docker run -d --name redis -p 6379:6379 redis:7          # or: redis-server
cd coding-interview/spring-boot
mvn spring-boot:run      # http://localhost:8080
./check-outputs.sh       # 12 integration tests against Redis; writes outputs/

    curl -i -X POST localhost:8080/api/v1/urls -H 'Content-Type: application/json' -d '{"url":"https://example.com/hello"}'
curl -i localhost:8080/s/1
curl -s localhost:8080/api/v1/restaurants/near?lat=12.97\&lon=77.59\&km=3

    How the tests work¶

    • @SpringBootTest + @AutoConfigureMockMvc (Boot 4 package org.springframework.boot.webmvc.test.autoconfigure) with the whole application against real Redis; FLUSHDB before each test.
    • A @Primary MutableClock replaces the Clock bean, so windows, versions and Snowflake timestamps are deterministic.
    • The quorum test starts the real server on a fixed port, so the coordinator calls replicas over HTTP.
    • Each test writes a request/response transcript; check-outputs.sh --check fails CI if a test fails or a transcript changes.

    Lessons the tests taught (they apply to interviews too)¶

    Why did a 200 ms quorum timeout make the first write fail?

    The first request hits a cold JVM (servlet initialisation, JIT, new HTTP connections) and all three replica calls exceeded 200 ms, so the coordinator correctly answered 503: 0/2 acks. Timeouts must cover p99 latency including warm-up, and production services warm up (or fail readiness) before taking traffic. The test profile uses 2 s.

    Why did read repair sometimes find nothing to repair?

    A write returns after W acks, but the other N − W requests are still in flight and can land later, so the "stale" replica had already caught up. That is how Dynamo-style stores converge. The coordinator now exposes an inFlight() count (a good gauge to export), and the test waits for it to reach zero before failing a replica.

    Why did invalid query parameters return 500 instead of 400?

    A class-level @Validated makes Spring wrap the controller in a validation proxy that throws ConstraintViolationException (500 unless you map it). Without it, Spring MVC's built-in method validation (Framework 6.1+) validates @RequestParam constraints and returns a 400 ProblemDetail.

    Why are Snowflake ids returned as strings?

    JavaScript numbers are doubles: integers above 2^53 lose precision, and a 63-bit Snowflake id would be silently corrupted in a browser.
