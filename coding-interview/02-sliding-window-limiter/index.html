    2. Sliding-Window Rate Limiter (Log vs Counter)¶

    L2 ★★☆ · Fixed-window burst problem, sliding log, weighted sliding counter

    Problem¶

    Limit each user to N requests per rolling minute. Show why a fixed window allows 2× bursts at the boundary, then implement an exact sliding log and a memory-cheap sliding counter, and compare them.

    Key idea¶

    Sliding log keeps the timestamp of every accepted request: exact, but O(N) memory per user (in Redis, a sorted set). Sliding counter keeps only the current and previous fixed-window counts and estimates previous × overlap + current: O(1) memory and slightly approximate. That's what Cloudflare runs at its scale. (Token bucket, which allows controlled bursts, is in the microservice playbook.)

    flowchart LR subgraph Prev["window 0:00–1:00 (count 10)"] end subgraph Cur["window 1:00–2:00 (count c)"] end Prev --> F["estimate at 1:15 = 10 × 0.75 + c"] Cur --> F F --> D{"< limit?"}

    Solution¶

    SlidingWindowRateLimiter.java
    import java.util.*;

/** Problem: limit each user to N requests per rolling window. Compare sliding LOG (exact) and sliding COUNTER (approximate). */
public class SlidingWindowRateLimiter {

    /** Exact: keep a timestamp per accepted request. Memory O(N) per user. (Redis: ZSET + ZREMRANGEBYSCORE + ZCARD) */
    static final class SlidingLog {
        private final int limit; private final long windowMs;
        private final Map<String, Deque<Long>> logs = new HashMap<>();
        SlidingLog(int limit, long windowMs) { this.limit = limit; this.windowMs = windowMs; }

        boolean allow(String user, long nowMs) {
            Deque<Long> log = logs.computeIfAbsent(user, u -> new ArrayDeque<>());
            while (!log.isEmpty() && log.peekFirst() <= nowMs - windowMs) log.pollFirst();   // drop expired
            if (log.size() >= limit) return false;
            log.addLast(nowMs);
            return true;
        }
    }

    /** Approximate: two fixed-window counters, weighting the previous window by its overlap. Memory O(1) per user. */
    static final class SlidingCounter {
        private final int limit; private final long windowMs;
        private final Map<String, long[]> state = new HashMap<>();   // [windowStart, currentCount, previousCount]
        SlidingCounter(int limit, long windowMs) { this.limit = limit; this.windowMs = windowMs; }

        boolean allow(String user, long nowMs) {
            long windowStart = nowMs - Math.floorMod(nowMs, windowMs);
            long[] s = state.computeIfAbsent(user, u -> new long[]{windowStart, 0, 0});
            if (s[0] != windowStart) {                                  // rolled into a new window
                s[2] = (windowStart - s[0] == windowMs) ? s[1] : 0;     // previous = last count, or 0 if we skipped windows
                s[1] = 0;
                s[0] = windowStart;
            }
            double overlap = 1.0 - (double) (nowMs - windowStart) / windowMs;
            double estimated = s[2] * overlap + s[1];
            if (estimated >= limit) return false;
            s[1]++;
            return true;
        }
    }

    /** The naive fixed window, for contrast: allows 2x the limit around a boundary. */
    static final class FixedWindow {
        private final int limit; private final long windowMs; private long windowStart = -1; private int count;
        FixedWindow(int limit, long windowMs) { this.limit = limit; this.windowMs = windowMs; }
        boolean allow(long nowMs) {
            long ws = nowMs - Math.floorMod(nowMs, windowMs);
            if (ws != windowStart) { windowStart = ws; count = 0; }
            return count < limit && ++count > 0;
        }
    }

    public static void main(String[] args) {
        int limit = 10; long window = 60_000;

        // Burst at the boundary: 10 requests at 0:59.9 and 10 at 1:00.1
        FixedWindow fixed = new FixedWindow(limit, window);
        SlidingLog log = new SlidingLog(limit, window);
        SlidingCounter counter = new SlidingCounter(limit, window);
        int fixedOk = 0, logOk = 0, counterOk = 0;
        for (int i = 0; i < 10; i++) { if (fixed.allow(59_900)) fixedOk++; if (log.allow("u", 59_900)) logOk++; if (counter.allow("u", 59_900)) counterOk++; }
        for (int i = 0; i < 10; i++) { if (fixed.allow(60_100)) fixedOk++; if (log.allow("u", 60_100)) logOk++; if (counter.allow("u", 60_100)) counterOk++; }
        System.out.println("20 requests in 200 ms across a window boundary (limit 10/min):");
        System.out.println("  fixed window   allowed " + fixedOk + "  <-- 2x burst");
        System.out.println("  sliding log    allowed " + logOk);
        System.out.println("  sliding counter allowed " + counterOk + "  (approximate: previous 10 x 99.8% overlap = 9.98 < 10 lets one more in)");
        check(fixedOk == 20 && logOk == 10 && counterOk <= limit + 1, "sliding algorithms stop the boundary burst");

        // Steady traffic: 1 request every 5 s for 3 minutes -> 12/min offered, 10/min allowed
        SlidingLog log2 = new SlidingLog(limit, window);
        SlidingCounter counter2 = new SlidingCounter(limit, window);
        int a = 0, b = 0;
        for (long t = 0; t < 180_000; t += 5_000) { if (log2.allow("u", t)) a++; if (counter2.allow("u", t)) b++; }
        System.out.println("36 requests evenly over 3 min: sliding log allowed " + a + ", sliding counter allowed " + b);
        check(a == 30 && Math.abs(a - b) <= 3, "counter approximates the log closely");
        System.out.println("PASS");
    }

    static void check(boolean ok, String what) { if (!ok) { System.out.println("FAILED: " + what); System.exit(1); } }
}

    Walkthrough¶

    Code Why
    while (log.peekFirst() <= nowMs - windowMs) log.pollFirst() Evict expired timestamps before counting. The deque stays sorted because time only increases.
    long windowStart = nowMs - Math.floorMod(nowMs, windowMs) Align to fixed windows. floorMod handles negative timestamps correctly.
    s[2] = (windowStart - s[0] == windowMs) ? s[1] : 0 On rollover, the old current count becomes the previous one, unless a whole window was skipped, in which case the previous count is 0.
    double estimated = s[2] * overlap + s[1] Weight the previous window by how much of it still falls inside the rolling window.
    sliding counter allowed 11 An honest approximation: at the boundary the previous 10 count as 9.98, so one extra request gets through. It assumes the previous window's traffic was uniform.

    Complexity¶

    Approach Time Space
    sliding log O(1) amortised O(limit) per user
    sliding counter O(1) O(1) per user
    fixed window O(1) O(1) but 2× bursts

    Solve it with Spring Boot 4¶

    The algorithms move into Redis Lua scripts, so "count, compare, record" is one atomic step shared by every instance. A Spring MVC HandlerInterceptor applies the limit before the controller and returns 429 with Retry-After and RateLimit-* headers. The algorithm is a property: ci.rate-limit.algorithm=SLIDING_LOG | SLIDING_COUNTER.

    sequenceDiagram participant C as Client participant I as RateLimitInterceptor participant L as RedisRateLimiter participant R as Redis (Lua) participant Q as QuoteController C->>I: GET /api/v1/quotes/INFY [X-User-Id: asha] I->>L: tryAcquire("asha") L->>R: EVALSHA sliding-log.lua (ZREMRANGEBYSCORE, ZCARD, ZADD) R-->>L: {allowed, remaining, retryAfterMs} alt allowed I->>Q: continue Q-->>C: 200 + RateLimit-Remaining else over the limit I-->>C: 429 + Retry-After (ProblemDetail) end
    sliding-log.lua
    -- Sliding LOG (exact). KEYS[1] = per-user sorted set of accepted request timestamps.
-- ARGV: now_ms, window_ms, limit, unique_member
local now, window, limit = tonumber(ARGV[1]), tonumber(ARGV[2]), tonumber(ARGV[3])
redis.call('ZREMRANGEBYSCORE', KEYS[1], '-inf', now - window)          -- drop expired entries
local count = redis.call('ZCARD', KEYS[1])
if count < limit then
  redis.call('ZADD', KEYS[1], now, ARGV[4])
  redis.call('PEXPIRE', KEYS[1], window)
  return {1, limit - count - 1, 0}                                       -- allowed, remaining, retry-after
end
local oldest = tonumber(redis.call('ZRANGE', KEYS[1], 0, 0, 'WITHSCORES')[2])
return {0, 0, oldest + window - now}                                     -- blocked until the oldest entry expires
    sliding-counter.lua
    -- Sliding COUNTER (approximate, O(1) memory). KEYS[1] = current window counter, KEYS[2] = previous window counter.
-- ARGV: now_ms, window_ms, limit
local now, window, limit = tonumber(ARGV[1]), tonumber(ARGV[2]), tonumber(ARGV[3])
local elapsed = now % window
local current = tonumber(redis.call('GET', KEYS[1]) or '0')
local previous = tonumber(redis.call('GET', KEYS[2]) or '0')
local estimated = previous * (1 - elapsed / window) + current
if estimated >= limit then
  return {0, 0, window - elapsed}
end
redis.call('INCR', KEYS[1])
redis.call('PEXPIRE', KEYS[1], window * 2)                               -- keep it while it is the "previous" window
return {1, math.max(0, math.floor(limit - estimated - 1)), 0}
    RedisRateLimiter.java
    package com.sdp.ci.p02ratelimit;

import java.time.Clock;
import java.util.List;
import java.util.concurrent.atomic.AtomicLong;
import org.springframework.core.io.ClassPathResource;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.data.redis.core.script.RedisScript;
import org.springframework.stereotype.Component;

/**
 * The interview algorithms moved into Redis Lua scripts, so check-and-increment is ONE atomic step
 * shared by every app instance (no read-then-write race between servers).
 */
@Component
public class RedisRateLimiter {
    public record Decision(boolean allowed, long remaining, long retryAfterMs) {}

    @SuppressWarnings("rawtypes")
    private static final RedisScript<List> SLIDING_LOG =
            RedisScript.of(new ClassPathResource("scripts/sliding-log.lua"), List.class);
    @SuppressWarnings("rawtypes")
    private static final RedisScript<List> SLIDING_COUNTER =
            RedisScript.of(new ClassPathResource("scripts/sliding-counter.lua"), List.class);

    private final StringRedisTemplate redis;
    private final RateLimitProperties props;
    private final Clock clock;
    private final AtomicLong seq = new AtomicLong();

    public RedisRateLimiter(StringRedisTemplate redis, RateLimitProperties props, Clock clock) {
        this.redis = redis;
        this.props = props;
        this.clock = clock;
    }

    @SuppressWarnings("unchecked")
    public Decision tryAcquire(String userId) {
        long now = clock.millis();
        long window = props.window().toMillis();
        String limit = String.valueOf(props.limit());
        List<Long> r = switch (props.algorithm()) {
            case SLIDING_LOG -> redis.execute(SLIDING_LOG, List.of("rl:log:" + userId),
                    String.valueOf(now), String.valueOf(window), limit, now + "-" + seq.incrementAndGet());
            case SLIDING_COUNTER -> {
                long windowStart = now - Math.floorMod(now, window);
                // Both keys share the {userId} hash tag, so they land on the same Redis Cluster slot.
                yield redis.execute(SLIDING_COUNTER,
                        List.of("rl:cnt:{" + userId + "}:" + windowStart, "rl:cnt:{" + userId + "}:" + (windowStart - window)),
                        String.valueOf(now), String.valueOf(window), limit);
            }
        };
        return new Decision(r.get(0) == 1L, r.get(1), r.get(2));
    }
}
    RateLimitInterceptor.java
    package com.sdp.ci.p02ratelimit;

import com.sdp.ci.common.Problems;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Component;
import org.springframework.web.servlet.HandlerInterceptor;

/** Runs before the controller: 429 + Retry-After when over the limit, RateLimit-* headers always. */
@Component
public class RateLimitInterceptor implements HandlerInterceptor {
    private final RedisRateLimiter limiter;
    private final RateLimitProperties props;

    public RateLimitInterceptor(RedisRateLimiter limiter, RateLimitProperties props) {
        this.limiter = limiter;
        this.props = props;
    }

    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object handler) {
        // Key by authenticated user in real systems; the header keeps the demo self-contained.
        String user = req.getHeader("X-User-Id") != null ? req.getHeader("X-User-Id") : req.getRemoteAddr();
        RedisRateLimiter.Decision d = limiter.tryAcquire(user);
        res.setHeader("RateLimit-Limit", String.valueOf(props.limit()));
        res.setHeader("RateLimit-Remaining", String.valueOf(d.remaining()));
        if (!d.allowed()) {
            long retrySeconds = Math.max(1, (d.retryAfterMs() + 999) / 1000);
            res.setHeader("Retry-After", String.valueOf(retrySeconds));
            throw Problems.of(HttpStatus.TOO_MANY_REQUESTS, "rate limit of " + props.limit() + " per "
                    + props.window().toSeconds() + "s exceeded; retry in " + retrySeconds + "s");
        }
        return true;
    }
}
    RateLimitConfig.java
    package com.sdp.ci.p02ratelimit;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.InterceptorRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration(proxyBeanMethods = false)
public class RateLimitConfig implements WebMvcConfigurer {
    private final RateLimitInterceptor interceptor;

    public RateLimitConfig(RateLimitInterceptor interceptor) { this.interceptor = interceptor; }

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(interceptor).addPathPatterns("/api/v1/quotes/**");   // only the protected API
    }
}

    What changes from the interview version¶

    Interview Production (Spring Boot 4)
    Map<String, Deque<Long>> per JVM Redis sorted set per user: one limit across all instances
    check then add (racy across servers) one Lua script = atomic check-and-record
    System.currentTimeMillis() injected Clock (tests move time; or use Redis TIME inside the script)
    returns boolean interceptor → 429, Retry-After, RateLimit-Limit/Remaining
    unbounded memory for idle users PEXPIRE on every key: idle users cost nothing

    The two counter keys share the {userId} hash tag so they hash to the same Redis Cluster slot, a requirement for multi-key scripts in a cluster. Gateways (Spring Cloud Gateway's RequestRateLimiter) ship a Redis token bucket built the same way.

    Common mistakes¶

    • A fixed window. Clients can send 2N within a second around each boundary.
    • Read-then-write in Redis without atomicity. Use a Lua script or MULTI, or two app servers will each allow the last slot.
    • Using the client's clock. Use the server's or Redis's time (TIME).
    • One global limiter key for all users, which creates a hot key. Shard by user id.

    Follow-up questions¶

    How do you rate-limit across 50 gateway instances?

    Use a central store (Redis) with an atomic script per request, or local limiters each with N/instances (cheap, approximate), or local token buckets refilled from a central budget periodically. Choose by how strictly the limit must hold.

    What should the response look like?

    429 Too Many Requests with Retry-After and RateLimit-Limit / RateLimit-Remaining / RateLimit-Reset headers, so well-behaved clients back off precisely.
